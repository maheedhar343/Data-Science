Foundation

Why Deep Learning?

Traditional ML (Module 4) requires you to hand-engineer features. For tabular data (loan, salary), this works well. For images, audio, and text — it breaks down completely.

A 224×224 colour image has 150,528 pixels. You cannot manually engineer features from 150K numbers. Deep learning learns its own features — from raw pixels to edges to shapes to objects — automatically, layer by layer.

The Core Idea

Deep learning = automatically learning hierarchical representations from raw data. Each layer transforms the data into a more abstract representation. No feature engineering required.

Session 1 · Neural Networks

The Artificial Neuron — Building Block of Everything

Every neural network — from a 3-layer network to GPT-4 — is composed of the same building block: the artificial neuron. Understanding it completely is the foundation of all deep learning.

🧠 Biological Analogy

A biological neuron receives signals from many dendrites. If the combined signal is strong enough, it fires and sends a signal through the axon to the next neuron. The artificial neuron does exactly this mathematically.

What a Neuron Computes — Step by Step

Step 1 — Weighted Sum: Multiply each input by its weight, add a bias.
z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b

Step 2 — Activation: Pass z through an activation function that introduces non-linearity.
output = activation(z)

The weights (w) and bias (b) are what the model learns during training.

🏦 Concrete Indian Example — Loan Approval Neuron

One neuron predicting loan default probability

Inputs: x₁ = monthly income (₹40,000), x₂ = CIBIL score (750), x₃ = employment years (5)
Learned weights: w₁ = 0.0001, w₂ = 0.008, w₃ = 0.3, bias b = −8.5
Weighted sum: z = 0.0001×40000 + 0.008×750 + 0.3×5 − 8.5 = 4 + 6 + 1.5 − 8.5 = 3.0
Sigmoid output: σ(3.0) = 0.95 → 95% probability of approval

Why "Deep"?

The word "deep" refers to the number of hidden layers. More layers = deeper network = ability to learn more abstract representations. A 1-layer network learns edges. A 5-layer network can learn faces. A 50-layer network can learn complex medical pathology.

📊
How many parameters does a network have? A network with 784 inputs, 2 hidden layers of 512 neurons each, and 10 output neurons has: (784×512 + 512) + (512×512 + 512) + (512×10 + 10) = 669,706 learnable parameters. Training = adjusting all these values.
Activation Functions

Activation Functions — The Non-Linearity Switches

Without activation functions, stacking layers just collapses back to a single linear equation — no matter how many layers you add. Activations introduce non-linearity so the network can learn complex, curved decision boundaries.

💡 Analogy

A dimmer switch (linear) can only control brightness proportionally. An on/off switch (step function) is too harsh. A ReLU is like a smart switch: off below zero, linearly proportional above zero — the best of both worlds.

ReLU

f(x) = max(0, x)

Returns x if positive, 0 if negative. The most commonly used activation today. Fast, sparse, works well in deep networks.

✅ Use: Hidden layers (default choice)

Sigmoid

f(x) = 1 / (1 + e⁻ˣ)

Squashes output to (0, 1). Historically used in hidden layers but causes vanishing gradients in deep networks. Now mostly relegated to output layers.

✅ Use: Binary classification output

Softmax

f(xᵢ) = eˣⁱ / Σeˣʲ

Converts a vector of numbers to a probability distribution — all outputs sum to 1.0. Tells you "how confident the network is about each class."

✅ Use: Multi-class classification output
🩺 Scenario — Choosing the right output activation

Problem: Classify an X-ray into: Normal / Pneumonia / COVID / Tuberculosis

This is 4-class classification — Softmax at the output gives [0.02, 0.87, 0.08, 0.03] → model is 87% confident it's Pneumonia. Binary diagnosis (Normal vs Abnormal) → Sigmoid → single probability.

How Networks Compute

Forward Propagation — One Full Pass

Forward propagation is simply the mathematical process of passing input through the network layer by layer to get a prediction. It happens in one direction — input to output.

Step-by-Step Forward Pass

Layer 1: Z¹ = W¹ · X + b¹ → A¹ = ReLU(Z¹)
Layer 2: Z² = W² · A¹ + b² → A² = ReLU(Z²)
Output: Z³ = W³ · A² + b³ → Ŷ = Sigmoid(Z³)

Each layer transforms the representation. The final output is the network's prediction.

🏪 Flipkart Product Classification

Input: Product image → Output: Category

Layer 1 neurons detect: brightness, edges, gradients
Layer 3 neurons detect: shapes — circles, rectangles
Layer 7 neurons detect: objects — mobile phone, shoe
Output: Softmax → [Electronics: 0.91, Fashion: 0.06, ...]

Loss Functions

Loss Functions — Measuring How Wrong You Are

After a forward pass, we need to measure how far the prediction is from reality. The loss function quantifies this error as a single number. Training minimises this number by adjusting weights.

The Goal of Training

Find the weights W and biases b that minimise the average loss across all training examples. Lower loss = predictions closer to reality = better model.

Loss FunctionTaskFormulaIndian Example
binary_crossentropy Binary Classification −[y·log(ŷ) + (1−y)·log(1−ŷ)] Fraud / No Fraud, TB / Normal
categorical_crossentropy Multi-Class −Σ yᵢ·log(ŷᵢ) X-ray: Normal/Pneumonia/COVID/TB
sparse_categorical_crossentropy Multi-Class (integer labels) Same as above Same — but labels are 0,1,2,3 not one-hot
mse Regression Σ(y − ŷ)² / n Predicting property price in Mumbai
📐 Intuition for Cross-Entropy Loss

If the true label is "Pneumonia" and the model predicts [0.01, 0.95, 0.03, 0.01] → Loss is very low (confident and correct). If prediction is [0.30, 0.30, 0.20, 0.20] → Loss is high (uncertain). If prediction is [0.90, 0.05, 0.03, 0.02] → Loss is very high (confident but wrong — worst case).

Backpropagation

Backpropagation — How Neural Networks Actually Learn

Backpropagation is the algorithm that distributes the blame for a wrong prediction back through the network, assigning each weight a gradient that tells it which direction to update — and by how much.

🎯 Analogy — Cricket Coach Reviewing a Match

Team India lost. The coach watches the match backwards — final over first, then the one before. He asks: "Who is most responsible for this loss?" and adjusts each player's strategy accordingly. Backprop does this mathematically using the chain rule of calculus.

→

Forward Pass — Make a Prediction

Input flows left to right through all layers. The network produces a prediction ŷ.

←

Compute Loss — How Wrong Was the Prediction?

Compare ŷ to the true label y using the loss function. Get a single error number L.

←

Backward Pass — Compute Gradients Layer by Layer

Using the chain rule, compute ∂L/∂W for every weight W — how much does the loss change if we change this weight slightly? Work backwards from output to input.

↑

Update Weights — Reduce the Loss

Adjust every weight in the opposite direction of its gradient: W = W − learning_rate × ∂L/∂W. Repeat for thousands of iterations.

💡
You never need to implement backpropagation yourself. TensorFlow and PyTorch compute gradients automatically using automatic differentiation. Calling model.fit() triggers the full forward → loss → backward → update cycle.
Optimisers

Gradient Descent — Navigating the Loss Landscape

Imagine the loss as a hilly landscape and you are blindfolded in it. Gradient descent tells you: "The slope is steepest downhill to your left — take a step left." Repeat until you reach the valley (minimum loss).

The Key Parameter — Learning Rate

The learning rate (α) controls how large each step is.
Too high → overshoots the minimum, loss oscillates or diverges.
Too low → training takes forever, may get stuck in local minima.
Typical range: 0.001 (Adam default) to 0.0001 (fine-tuning).

SGD (Stochastic)

Updates weights after each individual sample. Very noisy but can escape local minima. Rarely used alone — usually with momentum.

Academic research

Mini-Batch SGD

Updates after each mini-batch of 32–256 samples. Balances speed and stability. The most common training strategy.

Large datasets

Adam (Adaptive)

Adapts the learning rate per parameter based on gradient history. Usually converges faster and requires less tuning. Use Adam by default.

✅ Default choice
Python
model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss="binary_crossentropy",
    metrics=["accuracy", "AUC"]   # track multiple metrics
)
Regularisation

Overfitting — The #1 Problem in Deep Learning

Neural networks are so powerful they can memorise every training sample — including noise. The result is perfect training accuracy but terrible generalisation. This is the most important practical challenge in DL.

📏

Underfitting

Network too small or trained too few epochs. Train loss high, Val loss high. Fix: bigger network or more epochs.

🎯

Good Fit

Train loss ≈ Val loss, both low. The goal. Use early stopping to lock in this state.

🧠

Overfitting

Train loss very low, Val loss high and rising. Model memorised training data. Fix: Dropout, BatchNorm, more data, early stopping.

Three Regularisation Techniques
Dropout — Random Neuron Silencing

During each training step, randomly set p% of neurons to zero. Forces the network to learn redundant representations — no single neuron can dominate. Disabled at inference time.

Batch Normalisation

Normalises the activations of each layer within a mini-batch. Stabilises training, allows higher learning rates, acts as mild regularisation. Place it after Dense/Conv, before activation.

Early Stopping

Monitor validation loss. Stop training when it stops improving. Saves the best model weights. The simplest and most effective regularisation strategy.

Python
model = keras.Sequential([
    layers.Dense(256, activation="relu"),
    layers.BatchNormalization(),
    layers.Dropout(0.4),   # drop 40% of neurons
    layers.Dense(128, activation="relu"),
    layers.Dropout(0.3),
    layers.Dense(1, activation="sigmoid")
])

early_stop = keras.callbacks.EarlyStopping(
    monitor="val_loss", patience=5,
    restore_best_weights=True
)
Session 2 · CNNs

Why Standard Networks Fail on Images

A fully connected network treats each pixel as independent. It has no understanding that adjacent pixels are related — that a pixel and its neighbour form an edge, which forms a curve, which forms a shape.

The Problem — Spatial Ignorance

A 224×224×3 image flattened is a vector of 150,528 numbers. A single dense layer with 1024 neurons needs 150,528 × 1024 = 154 million weights — just for the first layer. This is untrainable and ignores spatial structure entirely.

👁 How You See vs How a Dense Network Sees

When you see a face, you don't process each pixel independently. Your visual cortex detects local features — edges in a small region, then corners, then parts, then whole faces. A CNN does exactly the same thing, hierarchically, using shared filters.

CNN's Three Innovations

1. Local Receptive Fields — each neuron only connects to a small patch (e.g., 3×3) of the previous layer, not the whole image.
2. Weight Sharing — the same filter (edge detector) slides across the entire image. Reduces parameters from millions to thousands.
3. Translation Invariance — if a dog is in the top-left or bottom-right, the same filter detects it. Works regardless of position.

📸 Scenario — ISRO Satellite Image Analysis

Detecting illegal construction in crop land from satellite imagery

A dense network sees 30M pixels independently — fails completely. A CNN's filters detect roads, buildings, vegetation boundaries layer by layer — achieves 92% accuracy on identifying unauthorised structures in Maharashtra farmland.

Convolution Operation

How Filters Detect Features

A filter (kernel) is a small matrix of learnable weights (e.g., 3×3). It slides across the image, computing a dot product at each position. The result is a feature map showing where that feature appears.

What Different Filters Detect

Vertical edge filter: Fires strongly on vertical lines — wall edges, door frames.
Horizontal edge filter: Fires on horizontal features — rooftops, horizons.
Gabor filter: Texture patterns at specific orientations.
Deep layer filters: Learn progressively complex features — curves, eyes, faces.

Feature Map = Input ★ Filter
(F_map)[i,j] = Σ Σ Input[i+m, j+n] × Filter[m,n]
(★ = convolution operator)
💡
Key parameters: filters = how many features to detect. kernel_size = how large each filter is (3×3 is standard). padding="same" keeps output same size as input.

Pooling Layer

Pooling — Compressing the Feature Maps

After convolution, feature maps are still large. Pooling downsamples them by summarising a region (e.g., 2×2) with a single value. This reduces computation, provides translation invariance, and focuses on dominant features.

Two Types of Pooling

Max Pooling (most common): Take the maximum value in each 2×2 region. Keeps the most activated feature — "was this feature detected anywhere in this region?"

Average Pooling: Take the average. Used in Global Average Pooling before the final Dense layer in modern architectures like MobileNet.

📐
Effect of MaxPool(2,2): Halves both spatial dimensions. A 224×224 feature map becomes 112×112. After 4 max-pool layers: 224 → 112 → 56 → 28 → 14. The final 14×14 map is then flattened and passed to Dense layers.

Transfer Learning

Transfer Learning — Standing on Giants' Shoulders

Training a CNN from scratch requires millions of images and days of GPU time. Transfer learning takes a model already trained on 1.2 million ImageNet images and adapts it to your specific task in minutes.

🏏 Cricket Analogy

A skilled batsman learning tennis doesn't start from scratch — they already have hand-eye coordination, footwork, and athletic reflexes. They only need to learn the specific tennis rules and swing mechanics. Transfer learning works the same way — the CNN already knows how to detect edges, textures, and shapes from ImageNet.

What gets transferred?

The early layers detect universal features — edges, gradients, textures, curves. These transfer to ANY visual domain (medical images, satellite photos, product images).

The late layers detect task-specific features (ImageNet classes: cats, dogs, cars). These are replaced with your task's output head.

Frozen vs Fine-tuned Layers

⚠️
Fine-tuning tip: After initial training with frozen base, unfreeze the last 20-30 layers and retrain with a 10× smaller learning rate (1e-5) for a further accuracy boost.
MobileNetV2

Transfer Learning Code

The complete pattern for any image classification task. Three phases: load base → add head → train head → optionally fine-tune.

Why MobileNetV2?

4.3MB model size (vs ResNet50's 98MB). Designed for mobile and edge deployment. Still achieves competitive accuracy. Inverted residuals + linear bottlenecks = efficient feature extraction with minimal parameters.

🏥 Lab Context

Chest X-Ray Pneumonia Detection

MobileNetV2 pretrained on ImageNet → Fine-tuned on 5,856 chest X-rays → 93.4% accuracy in detecting pneumonia vs normal lungs.

Python — transfer_learning_xray.py 
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

IMG_SIZE = 224
N_CLASSES = 2   # Normal vs Pneumonia

# ── Phase 1: Load pretrained base ─────────────────
base = keras.applications.MobileNetV2(
    input_shape=(IMG_SIZE, IMG_SIZE, 3),
    include_top=False,   # remove ImageNet output head
    weights="imagenet"
)
base.trainable = False   # freeze ALL base layers

# ── Phase 2: Add your classification head ─────────
inputs = keras.Input(shape=(IMG_SIZE, IMG_SIZE, 3))

# Preprocess inputs the way MobileNetV2 expects
x = keras.applications.mobilenet_v2.preprocess_input(inputs)

x = base(x, training=False)           # forward through frozen base
x = layers.GlobalAveragePooling2D()(x) # collapse spatial dims
x = layers.Dense(256, activation="relu")(x)
x = layers.Dropout(0.4)(x)
outputs = layers.Dense(N_CLASSES, activation="softmax")(x)

model = keras.Model(inputs, outputs)

# ── Phase 3: Compile and train the head ───────────
model.compile(
    optimizer=keras.optimizers.Adam(1e-3),
    loss="categorical_crossentropy",
    metrics=["accuracy", keras.metrics.AUC(name="auc")]
)

history = model.fit(
    train_ds, epochs=10,
    validation_data=val_ds,
    callbacks=[
        keras.callbacks.EarlyStopping(
            monitor="val_auc", patience=4,
            restore_best_weights=True, mode="max"
        )
    ]
)

# ── Phase 4: Fine-tune top 30 layers ──────────────
base.trainable = True
for layer in base.layers[:-30]:
    layer.trainable = False   # keep bottom layers frozen

model.compile(
    optimizer=keras.optimizers.Adam(1e-5),  # 100× smaller lr
    loss="categorical_crossentropy",
    metrics=["accuracy", keras.metrics.AUC(name="auc")]
)
model.fit(train_ds, epochs=5, validation_data=val_ds)
Data Augmentation

Data Augmentation — Creating More Training Data

Medical imaging datasets are small (thousands, not millions). Augmentation artificially expands the dataset by applying random transformations to each image at training time — teaching the model to be robust to variation.

Why Augmentation Works

A chest X-ray taken at slightly different angle, brightness, or zoom still shows the same pathology. By training on these variations, the model learns the invariant features — pneumonia consolidation, not the exact pixel values.

Python — tf.data augmentation pipeline
import tensorflow as tf

IMG_SIZE = 224
BATCH    = 32

# Augmentation layers (applied randomly at training time only)
augment = keras.Sequential([
    layers.RandomFlip("horizontal"),       # mirror left-right
    layers.RandomRotation(0.1),            # ±36 degrees
    layers.RandomZoom(0.1),                # ±10% zoom
    layers.RandomContrast(0.2),            # brightness variation
], name="augmentation")

def preprocess(image, label):
    image = tf.image.resize(image, [IMG_SIZE, IMG_SIZE])
    image = tf.cast(image, tf.float32) / 255.0
    return image, label

def load_dataset(path, training=True):
    ds = tf.keras.utils.image_dataset_from_directory(
        path, image_size=(IMG_SIZE, IMG_SIZE),
        batch_size=BATCH, label_mode="categorical"
    )
    if training:
        ds = ds.map(lambda x, y: (augment(x, training=True), y))
    return ds.prefetch(tf.data.AUTOTUNE)  # parallel loading

train_ds = load_dataset("chest_xray/train", training=True)
val_ds   = load_dataset("chest_xray/val",   training=False)
⚠️
Medical imaging caution: Don't flip vertically — an upside-down lung X-ray doesn't appear in clinical practice. Don't over-augment — extreme rotations or colour jitter can destroy clinically relevant features. Always validate augmentations with a domain expert.

🏥 Clinical Context — Why Recall Matters Most Here

A False Negative (missed pneumonia) means a sick patient goes home untreated — potentially fatal. A False Positive (healthy patient flagged) causes an unnecessary follow-up scan — inconvenient but not dangerous.

Therefore, optimise for Recall (catch every sick patient), even at the cost of more false alarms. Use a lower threshold (e.g., 0.3 instead of 0.5): flag more images for human review, miss fewer cases.

Python — adjust threshold for clinical use
from sklearn.metrics import recall_score, precision_score

# Adjust threshold for higher recall (clinical requirement)
for threshold in [0.3, 0.4, 0.5]:
    preds = (np.array(y_pred_proba) >= threshold).astype(int)
    r = recall_score(y_true, preds)
    p = precision_score(y_true, preds)
    print(f"Threshold={threshold}  Recall={r:.3f}  Precision={p:.3f}")

Common Pitfalls

Most Common Deep Learning Mistakes — and How to Fix Them

These are the mistakes every beginner makes. Recognising them early saves hours of debugging.

Mistake 1 — Not Normalising Input Images

Problem: Pixel values are in [0, 255]. Weights are initialised near 0. Large inputs cause exploding gradients.
Fix: Always scale to [0,1] (image / 255.0) or [−1,1] (image / 127.5 − 1, required for MobileNet).

Mistake 2 — Using the Wrong Loss Function

Binary classification (Normal vs Pneumonia) → binary_crossentropy + sigmoid output.
Multi-class (4 diseases) + one-hot labels → categorical_crossentropy + softmax.
Multi-class + integer labels → sparse_categorical_crossentropy + softmax.

Mistake 3 — Forgetting base.trainable = False

If you forget to freeze the base model, you will be retraining MobileNetV2 from scratch with your tiny dataset. This destroys the ImageNet weights and causes terrible performance. Always freeze first, train head, then optionally fine-tune.

Mistake 4 — Not using Early Stopping

Deep networks overfit silently. Without early stopping, you may run 50 epochs and the best model was at epoch 12. Always monitor val_loss or val_auc with restore_best_weights=True.

🚨
Mistake 5 — Data Leakage in Image Datasets: If you split your dataset after augmentation (not before), augmented versions of the same image end up in both train and test sets. Always split the raw dataset first, then augment only the training split.
Question 1 of 4
An AIIMS hospital wants to classify CT scans into 5 categories: Normal, Benign Tumor, Malignant Tumor, Infection, and Haemorrhage. They have 3,200 labelled scans. What is the correct setup?
ATrain ResNet50 from scratch with sigmoid output — medical images are different from natural images so ImageNet weights don't help
BFine-tune MobileNetV2 (ImageNet pretrained) with a softmax output of 5 units and categorical_crossentropy loss — pretrained features transfer well even to medical images, and 3,200 is too few to train from scratch
CUse 5 separate binary classifiers, each with sigmoid — one per disease class
DUse XGBoost with hand-crafted texture features — deep learning needs millions of samples
💡
Why B? Early CNN layers (edge/texture detectors) transfer to medical imaging — proven by many studies. With 3,200 samples, from-scratch training always overfits. Softmax + categorical_crossentropy is the standard for 5-class problems.
Question 2 of 4
After 10 epochs, your model shows Training Accuracy = 97%, Validation Accuracy = 61%, Validation Loss is increasing. What is the problem and the correct set of fixes?
AUnderfitting — increase model size, add more layers, train longer
BLearning rate is too high — reduce it to 1e-7 and retrain
CSevere overfitting — add Dropout (0.4–0.5), add BatchNormalization, use data augmentation, add early stopping, reduce model complexity
DData leakage — the validation set is accidentally included in training
⚠️
Diagnostic rule: Train acc ≫ Val acc + Val loss rising = textbook overfitting. The model has memorised the training set. Fix: regularisation (Dropout, BatchNorm), data augmentation, early stopping. Not a learning rate or architecture problem.

A startup is building a crop disease detection app that must run on a ₹6,000 Android phone with no internet. Their model achieves 91% accuracy but the APK crashes the phone. What should they do?
ASwitch to ResNet50 — it has better accuracy and will solve the performance issue

Question 4 of 4
Why does backpropagation use the chain rule of calculus, and what goes wrong with very deep networks (50+ layers) when using Sigmoid activation throughout?
AChain rule computes gradients in parallel — Sigmoid causes slow convergence but not incorrect results
BChain rule decomposes complex gradients into layer-wise multiplications. With Sigmoid, gradients are always in (0, 0.25) — multiplying 50 such small numbers gives a gradient ≈ 0 in early layers (vanishing gradient problem). Early layers stop learning. Use ReLU instead.
CChain rule is used because sigmoid has a known derivative. The deeper network issue is just a computational speed problem, solved with faster GPUs
DDeep networks with Sigmoid work fine — the problem only occurs with Tanh activations
💡
Vanishing Gradient — the historic problem that blocked deep learning: σ'(x) ≤ 0.25 always. After 50 layers: 0.25⁵⁰ ≈ 10⁻³⁰. Gradient is essentially zero. ReLU fixes this: gradient is either 0 (negative input) or 1 (positive input) — no shrinking through layers.
